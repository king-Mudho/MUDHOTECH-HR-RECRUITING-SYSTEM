# Recruiter guide

Creating vacancies, reviewing applications with AI assistance and proposing shortlists.

> **The rule that matters most:** the AI only suggests. You decide, and every decision that changes
> a candidate's status needs your reason. Missing information is *unknown*, never a fail.

## 1. Create a vacancy
1. **Jobs → New vacancy.** The wizard saves each step.
2. **Details:** title, department, location(s), employment type, salary (optional), closing date.
3. **Description:** write it in the editor; formatting is cleaned for safety.
4. **Criteria (the rubric):** skills, experience, qualifications, certifications, languages and
   questions, each with a weight. Mark the ones that are truly essential and say why.
   Suggestions from the AI are optional and labelled.
5. **Questions:** knock-out and screening questions. Questions about protected characteristics
   (age, gender, religion, tribe, marital status, health, disability, politics…) are refused.
6. **Submit for approval.** An HR manager approves and publishes. Once used, a vacancy version is
   fixed; changes create a new version.

## 2. Review applications
**Jobs → (vacancy) → Applicants** lists every application.
- Filter by status, AI band, essentials (met / unknown / not evidenced), flags or tags; save views
  you use often.
- **Bands are routing hints**, not decisions: *Recommended for review*, *Review needed*,
  *Eligibility review*, *Lower match*, *Manual review requested*. There is no reject band.
- **Blind review** is on by default: names, contact details and photos are hidden. Reveal identity
  only when needed; you must give a reason and it is logged.

Open an application to see:
- each criterion with its **evidence** (CV page and line, or the answer) — select a criterion to
  highlight the evidence; *unknown* means nothing was found, so ask rather than assume;
- **flags** such as a scanned CV, a non-English CV, or text that tried to instruct the AI (never
  penalised, always for a person to look at);
- the evaluation history (re-evaluation creates a new version).

Use **j / k** to move to the next / previous applicant from the list you came from.

**Verify** a claim you checked, or reject it with a note; the evaluation updates.
**Ask for clarification** when evidence is unknown or conflicting — the candidate is emailed.
**Compare** up to five applications side by side.

## 3. Propose a shortlist
1. **Shortlist** on the vacancy pre-fills AI suggestions only as a starting point.
2. Decide each applicant: *Shortlist*, *Not now* or leave undecided. When you differ from the AI
   suggestion, pick a reason — this is how the organisation learns whether the rubric works.
3. **Submit for approval.** The HR manager approves (and may return it with comments).

## 4. Good practice
- Read the evidence, not just the score. Check *unknown* essentials before deciding.
- Declare a conflict of interest if you know an applicant (you will no longer see that application).
- Never download CVs to personal devices; every view is logged.
