# 09 — Testing Strategy

## 1. Pyramid & tools
| Level | Tool | Scope | Gate |
|---|---|---|---|
| Unit | pytest, Vitest | services, ai_engine functions, utils, components | every commit |
| API/integration | pytest-django + DRF APIClient, factory_boy, real Postgres | endpoints, permissions, tenancy, transactions, outbox | every commit |
| Async | Celery `task_always_eager` for unit; real worker in integration job | idempotency, retries, ordering | every PR |
| Contract | drf-spectacular schema diff + openapi-typescript compile | API breaking changes | every PR |
| E2E | Playwright (Chromium + mobile emulation Pixel 7 / iPhone 13) | core journeys | every PR (smoke) + nightly (full) |
| Accessibility | @axe-core/playwright + manual keyboard/NVDA checklist | candidate & HR journeys | nightly + phase exit |
| AI quality | `ai_engine/tests/benchmark` with labelled synthetic set | extraction/matching metrics | phase 6/7/10 exits, nightly |
| Fairness | counterfactual tests | invariance to names/gender/location | every PR touching ai_engine |
| Security | Bandit, Semgrep, pip-audit, npm audit, Trivy, ZAP baseline (staging) | | nightly + pre-release |
| Load | Locust | submit 100/1,000 apps; dashboards | phase 10 |
| Resilience | fault injection (kill worker, stop Redis, S3 errors) | no lost submissions | phase 10 |
| Restore | backup/restore drill | RPO/RTO | phase 11 |

## 2. Mandatory test patterns
- **Tenancy**: `tests/tenancy/test_cross_tenant.py` parametrised over every staff endpoint: org B user gets 404 on org A objects (list excludes, detail 404, mutations 404).
- **Permissions matrix**: parametrised role × endpoint expected status table (`tests/permissions/matrix.py`).
- **State machine**: every allowed transition succeeds; every disallowed returns 409 `invalid_transition`; consequential transitions without human actor fail.
- **Idempotency**: repeat submit/approve with same key → identical response, single row.
- **Edge cases**: each EC-ID in `docs/07_EDGE_CASES.md` covered; `scripts/ec_coverage.py` greps tests for EC ids and reports missing ones (must be zero for implemented phases).
- **Audit**: sensitive actions assert an `AuditEvent` was written.

## 3. Fixtures & data
- `factories.py` per app; `make_org_with_team()`, `make_published_job(criteria=...)`, `make_submitted_application(cv="dev_strong.pdf")`.
- **Synthetic CV corpus** `backend/fixtures/synthetic_cvs/` generated by `scripts/generate_synthetic_cvs.py` (python-docx + reportlab): ≥ 150 CVs across 5 roles with variations: strong/partial/weak, equivalent wording, two-column, scanned (rasterised), tables, non-English, encrypted, corrupted, hidden text, injection, gaps, overlaps, attachment-only experience, Zimbabwean qualifications, foreign qualifications. Each has a `labels.json` gold record (claims + per-criterion expected evidence + HR reference suitability).
- Seed command `python manage.py seed_demo` creates: platform admin, 2 orgs (MudhoTech Demo Ltd, Acme Mining Zimbabwe), users per role, 3 published jobs (Software Developer, Accountant, Registered Nurse), 100 applications for Software Developer from corpus.
- No real personal data ever in fixtures.

## 4. Coverage targets
Backend services/ai_engine ≥ 85% lines; overall backend ≥ 80%; frontend features ≥ 70% for hooks/logic; 100% of EC ids for implemented phases.

## 5. AI acceptance thresholds (defaults — confirm with owner in Phase 10)
| Metric | Target |
|---|---|
| Parse success (text-based PDFs/DOCX) | ≥ 98% |
| Parse success incl. scanned | ≥ 90% (rest flagged, none lost) |
| Experience entry extraction F1 | ≥ 0.85 |
| Education level mapping accuracy | ≥ 0.90 |
| Skill extraction precision / recall | ≥ 0.85 / ≥ 0.80 |
| Recall of HR-qualified candidates in (recommended ∪ review_needed) | ≥ 0.95 |
| Grounding (every explanation sentence cited & supported) | 100% |
| Counterfactual invariance | 100% identical scores |
| Determinism (re-run) | 100% identical |

## 6. CI pipeline (`.github/workflows/ci.yml`)
1. Backend: ruff, mypy, `makemigrations --check`, pytest (Postgres+Redis services) with coverage, bandit, pip-audit.
2. Frontend: install (npm ci), lint, typecheck, vitest, build.
3. Contract: generate schema, compare against committed `schema.yml` (fail if uncommitted change), generate TS types and typecheck.
4. E2E smoke: docker compose up (CI profile), seed, Playwright smoke suite.
5. Build images + Trivy scan (on main).
